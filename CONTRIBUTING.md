## 🎯 Что можно контрибьютить

- **Мемы и фразы** — самый простой и самый ценный вклад.
- **Новые платформы для генератора** — префиксы, ядра, «для чего». Чем энтерпрайзнее, тем лучше.
- **Новые окна Win98** и **внезапные вставки**.
- **Звуки**: синтезированные в Web Audio. Свисток, гудок, фанфары синергии.
- **Режимы-кнопки** в духе «глупого деплоя».
- **Починка техдолга** — список в [`docs/SPEC.md`](docs/SPEC.md), §10. Онотоле особенно ценит такие PR.
- **Переводы.** Да, мы мечтаем о версии на английском. Да, олбанский тоже считается языком.

## 📜 Шесть заповедей платформы

Это не бюрократия, это архитектура. Нарушишь — платформа попячится. (Заповедей было пять, но платформа отмасштабировалась.)

1. **Один файл.** Весь сайт — это `index.html`. Никаких CDN, внешних шрифтов, картинок по ссылке и аудиофайлов. Файл должен работать, если его переслали в мессенджере и открыли без интернета.
2. **Звук только после клика.** Новый звук начинается со строки `if (!live()) return;`.
3. **Хаос с потолком.** Всё, что появляется на экране, либо исчезает по таймеру, либо ограничено по количеству. Платформа должна радовать, а не вешать вкладку.
4. **Три экрана.** Проверяем на десктопе (1440×900), телефоне (390×844) и телефоне боком (844×390).
5. **Мигание не чаще 3 раз в секунду.** Мы вырвиглазные, но заботливые.
6. **Офисный режим неприкосновенен.** Кнопка «🧘 пыщь без вспышек» включает `body.calm`. CSS-анимации выключаются там сами, а всё, что двигается из JS, должно проверять `calm`. Серьёзный блок дисклеймера о припадках не шутим и не олбанизируем — абсурд вокруг него, не внутри.

## ⚡ Как добавить мем за 30 секунд

Все тексты лежат массивами в начале `<script>` в `index.html`. Логику трогать не нужно.

| Хочу добавить | Массив |
|---|---|
| Фразу Упячки | `UPCHK` |
| Мем про Онотоле (только одобряющий!) | `ONOTOLE` |
| Олбанский / падонкафф | `PADONKI` |
| Монти Пайтон | `PYTHON` |
| Кусок для генератора платформ | `PRE`, `CORE`, `FOR`, `OPS` |
| Слоган платформы | `PITCH` |
| Строчку деплой-лога | `LOG` |
| Камент | `COMMENTS` (и ник в `NICKS`) |
| Отзыв | `REVIEWS` |
| Окно Win98 | `STATIC_POPUPS` |
| Фразу для синтеза речи | `SPEECH` |
| Менеджерский язык в духе «Совы — эффективного менеджера» | `MANAGER` |
| Расшифровку GSOM | `GSOM_WORDS` (слова на G/S/O/M), `GSOM_TAIL` (хвосты «… Edition») |
| Способ, которым уходит проигнорированное окно | `WIN_EXITS` + CSS `.win.x-<kind>` |
| Трек для УПЧК-ампа | `TRACKS` (формат — `docs/SPEC.md` §6.12; мелодия только своя) |

Пример:

```js
const PITCH = [
  // ...
  "Совместимо с YAML, Excel и здравым смыслом (частично)",
];
```

## 🧭 Правила лора

Наш юмор — это добрый абсурд в духе рунета нулевых.

**Приветствуется:**
- язык Упячки: попячтсо, пыщь, глагне, стопицот, котэ, пепякодэнс, голактеко опасносте;
- олбанский: аффтар жжот, зачот, превед, йа креведко;
- Монти Пайтон, переделанный под энтерпрайз;
- Великий Онотоле в канонической одобряющей гиперболе: знает всё, семь мозгов, одобряе;
- любые баззворды: синергия, Zero Trust, data mesh, golden path, импортозамещение импортозамещения.

**Не принимаем:**
- мат и туалетный юмор — у нас семейная синергия;
- политиков и политику;
- шутки про реальных частных людей;
- мемы про причинение вреда себе или другим;
- оскорбления групп людей — по любому признаку;
- выдуманные цитаты реальных людей (Онотоле одобряе — можно, «Онотоле сказал: …» — нельзя);
- чужих персонажей и картинки (рисуем только эмодзи, CSS и свой SVG);
- тексты песен и чужие мелодии (от песни-мема берём максимум название, ноты пишем свои).

Если сомневаетесь, спросите себя: «Улыбнётся ли человек, про которого эта шутка?» Если да — несите в PR.

## 🌿 Ветки и коммиты

### GitHub flow: main священен, всё через фича-ветки

В `main` напрямую не коммитим и не пушим — ни мейнтейнеры, ни Онотоле (ему и не нужно, он и так всё знает). `main` всегда зелёный и всегда готов к деплою на Pages; любое изменение приходит в него через PR.

```
main ──●───────────────●─── (только мержи PR)
        \             /
         ● ─ ● ─ ●  ─ PR ─ ⚖️ Вердикт Онотоле ✅ ─ ревью ✅
       feature/синергия-с-блокчейном
```

1. **Ветка от свежего `main`:**
   ```bash
   git switch main && git pull --ff-only
   git switch -c feature/синергия-с-блокчейном
   ```
2. **Коммиты** — маленькие и через валидатор (см. ниже). `npm test` перед каждым пушем.
3. **Пуш ветки и PR в `main`:** `git push -u origin feature/синергия-с-блокчейном`, дальше «Compare & pull request» на GitHub. Шаблон PR сам подсунет чек-лист. Не готово — открывайте черновик (Draft): CI гоняется и для него.
4. **CI** запускается на каждый пуш в PR, устаревший прогон отменяется сам. Пуш в ветку без PR CI не трогает — откройте PR, и Онотоле посмотрит.
5. **Мерж** — когда «⚖️ Вердикт Онотоле» зелёный и есть ревью. Предпочитаем **Rebase and merge** или **Merge commit**: каждый пыщь-коммит уже прошёл валидатор, и `CHANGELOG` с историей должны их видеть. Squash — только если ветка превратилась в «wip, wip, ну теперь точно». После мержа ветку удаляем.
6. **Отстали от `main`** — `git rebase main` (или merge, если ветку уже кто-то забрал), снова `npm test`, `git push --force-with-lease`. Голый `--force` попячит чужую работу.

**Имена веток** — префикс по типу изменения, дальше пара слов через дефис:

| Префикс | Когда |
|---|---|
| `feature/` | новая фича, режим, трек, окно |
| `fix/` | починка |
| `meme/` | только мемы и тексты в массивах |
| `docs/` | только документация |
| `ci/` | тесты, GitHub Actions, инструменты |

```
feature/синергия-с-блокчейном
fix/монолит-не-отдыхает
meme/ещё-больше-креведко
```
Латиница тоже подойдёт и в терминале набирается проще: `feature/more-synergy`.

### 🛡️ Защита `main` (для мейнтейнеров, один раз)

Settings → Rules → Rulesets → New branch ruleset, цель — ветка по умолчанию:
- **Restrict deletions** и **Block force pushes**;
- **Require a pull request before merging** — 1 одобрение (в соло-проекте можно 0, но PR всё равно обязателен);
- **Require status checks to pass** → `⚖️ Вердикт Онотоле` и **Require branches to be up to date**.

Вердикт ждёт все остальные джобы, поэтому обязательной достаточно сделать только его. Переименуете джобу — поправьте и правило, иначе PR будет вечно ждать проверку, которой больше нет (статический тест `tests/static/ci.test.mjs` напомнит).

### Коммиты

Пишем по [Conventional Commits](https://www.conventionalcommits.org/ru/), смешно, но честно: заголовок говорит, что изменилось, а шутки живут в хвосте, теле и трейлерах.

Если вы работаете в Claude Code, в репозитории уже лежит скилл `pyshch-commit` (`.claude/skills/pyshch-commit/`): просто скажите «закоммить», и он напишет коммит в стиле платформы. Без Claude сообщение можно проверить тем же валидатором:

```bash
python3 .claude/skills/pyshch-commit/scripts/check_message.py путь/к/сообщению.txt
```

Скоупы из нашей вселенной:

| Скоуп | Про что |
|---|---|
| `glagne` | главная страница, верстка |
| `onotole` | печати и мемы про Онотоле |
| `generator` | генератор платформ |
| `olbanian` | олбанский режим |
| `audio` | звуки и речь |
| `popups` | окна Win98 |
| `interrupts` | внезапные вставки |
| `krevedko` | всё остальное, что вызывает умиление |

Примеры:
```
feat(generator): добавить префикс «Гиперконвергентно»
fix(glagne): кнопка ПОПЯЧЬСЯ больше не убегает за экран на iPhone SE
perf(glagne): кешировать ширину летающих надписей, синергия +12%
docs: объяснить инвестору, что такое стопицот
```

## ✅ Проверка перед PR

1. Откройте `index.html` в браузере, прочитайте дисклеймер (да, целиком — EULA сам себя не примет) и нажмите «ЖМИ ЧТОБ ПЫЩЬ».
2. Понажимайте все кнопки, особенно ту, которую добавили вы.
3. Проверьте, что консоль браузера чистая.
4. Перезагрузите и войдите через «🧘 пыщь без вспышек»: ваша фича не должна мигать, трястись и пульсировать.
5. Прогоните тесты — те же, что гоняет CI:
   ```bash
   npm ci                                  # одна dev-зависимость: @playwright/test
   npx playwright install chromium         # один раз
   npm test                                # статика + браузерные тесты на трёх экранах
   ```
   Быстрый круг без браузера — `npm run test:static` (лор, такты треков, `live()`, вспышки, офисный режим). Один экран — `npx playwright test --project=phone`.
6. Упало — смотрите скриншот и трейс в `test-results/` (`npx playwright show-trace …`). Новая фича — новый тест в `tests/e2e/` или `tests/static/`, Онотоле любит, когда его одобрение подкреплено фактами.
7. Трогали звук — проверьте на телефоне, если он есть: на iOS звук засыпает после сворачивания Safari, а дисктоячка должна просыпаться по тапу.

### 🛸 Онотоле CI

На каждый пуш в PR и после мержа в `main` GitHub Actions запускает `.github/workflows/ci.yml`. Сторонние actions прибиты к SHA коммита — обновляем их осознанно, отдельным PR в `ci/`-ветке:

| Джоба | Что проверяет всерьёз |
|---|---|
| 🔤 Олбанский линтер | `npm run test:static`: один файл без внешних запросов, звук только через `live()`, мигание не быстрее .2s, `body.calm` для JS-анимаций, серьёзный блок дисклеймера, такты и форма треков, запрещённые мемы |
| 💨 Попячтсо-тесты · desk/phone/land | Playwright на трёх экранах: старт, кнопки, дисклеймер и офисный режим, все треки, шаффл, окна, iOS-сценарии звука, лимиты DOM, ни одного сетевого запроса. Упало — скриншоты и трейсы в артефактах |
| 💬 Пыщь-коммиты | каждый коммит PR через валидатор `pyshch-commit` |
| ⚖️ Вердикт Онотоле | собирает итог в summary: «ОНОТОЛЕ ОДОБРЯЕ» или «ОНОТОЛЕ НЕГОДУЕ». Единственная обязательная проверка в защите `main` |

## 👀 Как проходит ревью

Ревью у нас проводит Совет Онотоле (мейнтейнеры). Вердикты переводятся так:

| Вердикт | На языке GitHub |
|---|---|
| **Онотоле одобряе** ✅ | Approve |
| **Онотоле размышляе** 🤔 | Comment |
| **Онотоле просит попячиться** ↩️ | Request changes |
| **Зачот** 🎉 | Merged |

«Попячиться» — это не обидно. Это просто значит «давай чуть-чуть поправим». Даже у Онотоле бывают правки, просто он их делает до того, как вы о них подумали.
