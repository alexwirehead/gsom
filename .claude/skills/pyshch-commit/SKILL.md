# Пыщь-коммит

Скилл превращает коммиты в маленькие праздники, не ломая историю git. Хороший пыщь-коммит смешной при чтении целиком, но его заголовок в `git log --oneline` всё равно честно говорит, что изменилось. Через полгода кто-то будет искать баг через `git bisect`, и шутка не должна ему мешать.

## Главное правило: сначала правда, потом пыщь

Юмор украшает коммит, но не заменяет информацию.

- **Тип и суть изменения в заголовке должны быть точными.** `fix(glagne): кнопка ПОПЯЧЬСЯ не уезжает за экран на iPhone SE` — хорошо. `feat: синергия!!!11` — плохо, потому что из него ничего не понятно.
- **Каждое утверждение в теле про код должно быть правдой.** Шутки отделяются от фактов: факт — это строка про то, что сделано, шутка — это комментарий к нему или отдельная строка. Не выдумывай изменения, метрики производительности и тесты, которых не было. «Синергия +146%» — понятная шутка; «ускорили рендер на 40%» без замеров — враньё.
- **Шуточные «breaking changes» не пишутся как настоящие.** `!` после типа и трейлер `BREAKING CHANGE:` читают semantic-release, commitizen и changelog-генераторы: они поднимут мажорную версию. Для космических шуток используй трейлер `Cosmic-Change:` (см. ниже). Настоящий `BREAKING CHANGE:` ставится только при настоящем ломающем изменении.

## Порядок работы

### 1. Собрать контекст

Запусти скрипт из папки скилла, он ничего не меняет в репозитории:

```bash
bash <путь-к-скиллу>/scripts/commit_context.sh
```

Он покажет ветку, статус, статистику и дифф застейдженного, последние коммиты, наличие commitlint и настройку уровня абсурда в CLAUDE.md. Если скрипт недоступен, выполни то же вручную: `git status --short`, `git diff --staged --stat`, `git diff --staged`, `git log -n 15 --oneline`.

**Если ничего не застейджено**, не делай `git add -A` молча. Покажи, что изменено, и спроси, что включить в коммит. Если пользователь явно сказал «закоммить всё» — тогда можно.

### 2. Подстроиться под репозиторий

- **Язык** — как в последних коммитах. В русскоязычном репо пиши по-русски, в англоязычном — по-английски, перенося юмор (см. `references/lore.md`, раздел «English mode»).
- **Скоупы** — бери из истории коммитов и CONTRIBUTING.md. В gsom-ee это `glagne`, `onotole`, `generator`, `olbanian`, `audio`, `popups`, `interrupts`, `krevedko`.
- **commitlint** — если в репо есть его конфиг, соблюдай `type-enum`, регистр и максимальную длину заголовка. Конфиг важнее любой шутки.

### 3. Выбрать уровень абсурда

| Уровень | Когда | Как выглядит |
|---|---|---|
| **1 — Офисный пыщь** | рабочий репо, «потише», «чтобы тимлид не плакал» | обычный заголовок, одна лёгкая шутка в теле или трейлере |
| **2 — Синергия** (по умолчанию) | обычный весёлый коммит | шутливый хвост в заголовке, тело из фактов с комментариями, 1–2 трейлера |
| **3 — Стопицот** | «на максимум», «жги», первый коммит, релиз | абсурд во всё тело, несколько трейлеров, олбанские вставки — но заголовок всё равно честный |

Уровень берётся из слов пользователя, затем из строки `pyshch-commit: level N` в CLAUDE.md, иначе 2.

### 4. Понять изменение

Прочитай дифф и сформулируй для себя одной фразой, что и зачем поменялось. Если в стейдже несколько независимых изменений (например, фича и несвязанный рефакторинг), предложи разбить на несколько коммитов — так история полезнее, а шуток будет больше.

### 5. Написать сообщение

```
<type>(<scope>): <что сделано, в повелительном или прошедшем стиле репо> — <шутливый хвост?>

- <факт>; <шутка-комментарий?>
- <факт>
- <чистая шутка, если уровень ≥ 2>

<Трейлер>: <значение>
```

**Заголовок:**
- до 72 символов (или сколько разрешает commitlint). Русский текст съедает лимит быстро, а шутливый хвост соблазняет его раздуть. Если хвост не влезает — он уезжает в тело, суть изменения в заголовке важнее;
- тип по смыслу: `feat`, `fix`, `perf`, `refactor`, `docs`, `test`, `style`, `chore`, `ci`, `build`, `revert`;
- шутливый хвост через « — » только если влезает и не мешает смыслу. На уровне 1 хвоста нет.

**Тело:** 2–6 строк. Сначала факты, шутки рядом с ними. Объясняй «зачем», если это не очевидно, — это делает коммит полезным, а не только смешным.

**Трейлеры** — только нестандартные и безобидные:

| Трейлер | Пример |
|---|---|
| `Onotole-Verdict:` | `одобряе` / `размышляе` / `негодуе, но мёрджит` |
| `Synergy:` | `+146%` |
| `Pyshch-Level:` | `!!!11адинадин` |
| `Cosmic-Change:` | `вселенная теперь происходит из бороды Онотоле` |
| `Krevedko-Approved:` | `yes` |
| `Spam-Count:` | `spam, spam, eggs and spam` |

Никогда не добавляй фейковые `Co-authored-by:`, `Signed-off-by:` и `Reviewed-by:` — GitHub и DCO-боты принимают их всерьёз и могут привязать коммит к реальному чужому аккаунту по email.

### 6. Проверить

Сохрани сообщение во временный файл и прогони валидатор:

```bash
python3 <путь-к-скиллу>/scripts/check_message.py "$msg"        # или --max N из commitlint
```

Он ловит длинный заголовок, нарушение Conventional Commits, отсутствие пустой строки, фейковые трейлеры авторства и запрещённую лексику, а ещё предупреждает про `BREAKING CHANGE`. На глаз длину не считай — проверено, что глаз ошибается в сторону синергии. Если валидатор негодуе — поправь и прогони снова.

### 7. Показать и закоммитить

Покажи сообщение пользователю (и вердикт валидатора). Коммить только после подтверждения («да», «го», «пыщь»). Пиши сообщение во временный файл и коммить через `-F` — так не ломаются кавычки, переносы и `%`:

```bash
msg=$(mktemp) && cat > "$msg" << 'MSG'
...сообщение...
MSG
git commit -F "$msg" && rm -f "$msg"
```

Не используй `--no-verify`, `--amend`, `push` и `--force`, если пользователь об этом явно не попросил. Если упал pre-commit-хук — покажи ошибку и предложи починить, а не обходить.

Если пользователь просит «ещё вариант» — дай другой хвост и другие шутки, не меняя фактов.

## Гайдлайны юмора

Смеёмся над баззвордами, процессами, легаси и собой — не над людьми.

**Можно:** Упячка (попячтсо, пыщь, глагне, стопицот, котэ, пепякодэнс, голактеко опасносте), олбанский (аффтар жжот, зачот, превед, йа креведко), Монти Пайтон (спам, рыцари, говорящие «Ни!», испанская инквизиция, «это всего лишь царапина», мёртвый попугай), энтерпрайз (синергия, Zero Trust, golden path, data mesh, импортозамещение импортозамещения), Великий Онотоле в одобряющей гиперболе.

**Нельзя:**
- мат, туалетный юмор и всё, что намекает на него;
- политика, политики, религия;
- шутки про реальных людей, кроме канонического одобряющего Онотоле; не выдумывай ему цитат;
- шутки над авторами кода, который чинишь: `fix: починил говнокод Васи` — нет, `fix: монолит признал, что это была не царапина` — да;
- мемы про причинение вреда себе или другим;
- секреты, токены и куски приватных данных из диффа — даже ради шутки.

Если сомневаешься, проверь: улыбнётся ли автор исправленного кода, прочитав коммит? Если нет — переписать.

Банк фраз, привязка шуток к типам изменений и английский режим лежат в `references/lore.md`. Загляни туда, когда нужна свежая шутка, чтобы коммиты не повторялись.

## Примеры

**Уровень 2, фикс:**
```
fix(glagne): не выпускать кнопку ПОПЯЧЬСЯ за экран — хватит эмигрировать

- позиция кнопки зажимается по размерам окна с учётом бегущих строк
- пересчёт при resize: раньше после поворота телефона кнопка уходила в метавселенную
- поймать её всё равно можно только с четвёртой попытки — это фича

Onotole-Verdict: одобряе
```

**Уровень 2, производительность:**
```
perf(glagne): кешировать ширину летающих надписей — без layout thrash

- offsetWidth читается только при смене текста, а не 60 раз в секунду на надпись
- tick() больше не устраивает layout thrash; монолит говорит, что это была не царапина
- поведение не изменилось, надписи летают так же абсурдно

Synergy: +146%
Krevedko-Approved: yes
```

**Уровень 1, документация:**
```
docs: описать порядок добавления новых окон в CONTRIBUTING

- таблица массивов дополнена STATIC_POPUPS и полем special

Onotole-Verdict: одобряе
```

**Уровень 3, первый коммит:**
```
feat(glagne): initial popyachtso — навайбкодили платформу платформ

- один HTML-файл без зависимостей: генератор платформ, печати Онотоле, окна Win98
- синтез звуков и речи в браузере, адаптив под десктоп и телефон
- тесты не нужны, ИИ сказал, что всё зелёное (шутка: smoke-тест лежит в tests/)
- пепякомэн танцует, котэ деплоит в прод, голактеко в безопасносте

Cosmic-Change: вселенная теперь происходит из бороды Онотоле
Pyshch-Level: !!!11адинадин
Synergy: +146%
```

**Revert:**
```
revert: ПОПЯЧТСО «feat(audio): добавить волынку на каждый клик»

- откатывает a1b2c3d: волынка оказалась слишком синергичной для соседей

Onotole-Verdict: размышляе
```
